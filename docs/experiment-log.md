# 迷宫寻路算法可视化系统实验记录

## 一、实验目标

使用 Python 和 Pygame 开发互动迷宫，展示 BFS、DFS 和 A* 的搜索过程，比较路径长度、探索节点数和算法耗时，并通过自动化测试检查算法行为。

迷宫采用二维网格，只允许上下左右移动，每步代价为1。

## 二、开发方式与文件分工

采用 Vibe Coding 方式分阶段开发：描述需求，借助 AI 生成代码，在 VS Code 中运行，反馈运行结果，再进行修改和验证。

主要文件：

| 文件 | 作用 |
|---|---|
| main.py | 迷宫交互、键盘与鼠标操作、动画绘制 |
| algorithms.py | BFS、DFS、A* 算法及搜索顺序记录 |
| benchmark.py | 同地图性能对比 |
| tests/test_algorithms.py | 算法自动化测试 |

## 三、实验步骤

### 1. 绘制迷宫与编辑障碍

创建20行、20列的网格。使用二维列表保存迷宫，0表示道路，1表示障碍。

实现鼠标左键绘制障碍、右键擦除障碍、C键清空障碍，并保护起点和终点不被涂成障碍。

截图：01_互动迷宫编辑.png。

### 2. 设置起点与终点

鼠标指向目标格子，按S设置起点，按E设置终点。

禁止起终点重叠；在障碍格上设置起点或终点时，清除该格障碍。

截图：02_自由设置起点终点.png。

### 3. 实现BFS寻路

使用先进先出的队列逐层探索，使用前驱记录恢复路径。

按空格运行BFS。存在通路时显示黄色路径及步数，无解时显示提示。修改地图后清除旧结果，支持重新搜索。

截图：

- 03_BFS最短路径.png
- 04_BFS无解提示.png
- 05_修改地图后重新寻路.png

### 4. 展示搜索过程

算法先记录探索顺序，界面再按固定时间间隔播放。

蓝色表示已探索格子，黄色表示最终路径，绿色和红色分别表示起点和终点。最终路径颜色覆盖探索颜色。

修改地图或清空地图时，取消旧动画并清除旧结果。

截图：06_BFS探索区域与最终路径.png。

### 5. 加入DFS并比较路径

使用后进先出的栈实现DFS，按D运行。

在20×20空白地图上，将起点设为左上角、终点设为右下角。当前实现中，DFS得到190步路径，BFS得到38步路径，展示了DFS不保证最短路径的特点。

截图：

- 07_DFS搜索结果.png
- 08_同地图BFS对比结果.png

### 6. 加入A*搜索

使用优先队列，按照 f = g + h 选择探索位置。

g为从起点到当前格子的已知路径代价，h为到终点的曼哈顿距离。f相同时优先选择h较小的格子。

按A运行A*。在已演示的空白地图与障碍地图中，BFS和A*均得到38步最短路径；障碍地图中，A*的探索范围明显更小。

截图：

- 09_同地图A星搜索结果.png
- 10_障碍地图BFS结果.png
- 11_障碍地图A星结果.png

### 7. 性能对比

按P，在当前相同地图和起终点下运行三种算法。

探索节点数单独记录。耗时测量不记录动画顺序、不包含绘图和动画播放，每种算法预热后运行100次取平均。

20×20空白地图、起点(0, 0)、终点(19, 19)的本次实测结果：

| 算法 | 路径步数 | 探索节点数 | 平均耗时（毫秒） |
|---|---:|---:|---:|
| BFS | 38 | 400 | 0.2208 |
| DFS | 190 | 229 | 0.1410 |
| A* | 38 | 39 | 0.0543 |

在这一案例中，A*既得到最短路径，也探索了最少的节点，平均耗时最低。DFS此次比BFS耗时少，但路径更长。

这些结果只代表本次地图与运行条件，不说明某一种算法在所有地图上都更快。

截图：12_三种算法性能对比.png。

### 8. 自动化测试

使用pytest运行17项测试，检查：

- 路径起终点、边界、障碍及相邻步是否合法。
- 无解时是否返回空列表。
- 起终点相同时是否返回零步路径。
- 是否禁止对角移动。
- BFS、A*在指定绕行案例中是否返回8步最短路径。
- 算法是否保持原地图不变。

运行结果：17 passed in 0.04s。

其中0.04秒是本次整套测试的运行时间，不是单个寻路算法耗时。通过这些测试说明列出的案例符合要求，不代表覆盖所有可能情况。

截图：13_算法自动化测试结果.png。

## 四、实验结论与局限

系统完成了迷宫编辑、三种寻路算法、搜索过程播放、性能对比和基础自动化测试。

在当前等步长、四方向移动规则下，BFS与使用曼哈顿距离的A*保证最短路径；DFS不保证最短路径。最短路径可能不唯一，因此路线不同但步数相同可以都是正确结果。

当前地图只保存在内存中，关闭程序后不会保存。搜索动画属于探索记录的回放，动画时长不能用于衡量算法速度。后续可扩展地图保存、随机迷宫和更多测试案例。

## 五、第二轮功能完善

### 1. 中文操作面板

在迷宫右侧增加中文操作面板，提供BFS、DFS、A*、性能对比、重置搜索和清空障碍按钮，并保留原有快捷键。

明确区分两个操作：

- 重置搜索：清除搜索颜色及结果，保留障碍和起终点。
- 清空障碍：清除障碍和搜索结果，保留起终点。

运行时发现自动查找系统字体出现异常，改为直接加载Windows中文字体文件后正常显示。

人工验证了各按钮、地图编辑及算法搜索功能。

截图：14_中文操作面板.png。

### 2. 地图保存与加载

新增map_storage.py，使用JSON文件保存障碍、起点和终点，保存位置为maps/saved_maze.json。

保存时先写入临时文件，写入成功后替换旧文件。加载时检查地图尺寸、格子取值、端点坐标、障碍占用及端点重叠情况。

通过“保存地图—修改地图—加载地图”及关闭程序后重新加载，验证地图能够恢复。搜索动画和搜索颜色不保存。

本项不附截图。

### 3. 动画暂停与速度调节

增加F6暂停与继续，以及方向键调整播放速度，共5档。

动画暂停时窗口仍响应操作。重置或开始新搜索时清除暂停状态，避免新搜索仍停留在暂停状态。

验证内容包括暂停、继续、调速，以及暂停后重置并重新运行算法。

这些操作只控制搜索记录的播放，不改变算法结果或性能计时方法。

### 4. 窗口内性能对比表

点击性能对比按钮后，在右侧面板显示三种算法的路径步数、探索节点数和平均耗时，并保留终端输出。

表格直接使用性能测量函数返回的数据。有结果时替换下方操作说明；修改地图、加载地图或重置搜索后清除旧表格，避免展示过时结果。

验证窗口与终端的数据一致，修改障碍后旧表格消失，重新比较后显示新结果。

### 5. 预设迷宫

新增presets.py，提供三种固定场景：

| 快捷键 | 地图 | 验证结果 |
|---|---|---|
| F1 | 空白地图 | BFS和A*最短路径均为38步 |
| F2 | 两道墙的绕行地图 | BFS和A*最短路径均为72步 |
| F3 | 起点被封住的无解地图 | 三种算法均无解，探索节点数均为1 |

切换预设会替换当前地图、恢复预设起终点，并取消旧动画、清除搜索结果。

人工验证了搜索动画播放期间切换预设的行为。

### 6. 绕行地图性能实验

在相同的F2绕行地图上，保持起终点与移动规则一致，每种算法运行100次，得到本次实测结果：

| 算法 | 路径步数 | 探索节点数 | 平均耗时（毫秒） |
|---|---:|---:|---:|
| BFS | 72 | 362 | 0.2019 |
| DFS | 192 | 194 | 0.1145 |
| A* | 72 | 255 | 0.3336 |

BFS与A*得到相同的最短路径长度，DFS返回较长的可行路径。

本次A*探索节点少于BFS，但耗时更长。优先队列维护、启发值计算等额外开销可能抵消减少探索带来的收益，测量也会受到运行波动影响。因此不能将“探索节点更少”等同于“运行一定更快”。

这些数值是本次实验记录，不作为每次运行必须达到的标准。

### 7. 扩展自动化测试

新增tests/test_maps.py，在原有17项测试基础上增加17项，共34项。

新增检查包括：

- 地图保存和加载后数据一致。
- 未找到地图文件时正确报错。
- 损坏的JSON文件被拒绝。
- 非法尺寸、格子值、越界端点、障碍上的端点和重叠端点被拒绝。
- 空白与绕行预设的最短路径分别为38步和72步。
- 无解预设中三种算法只探索起点。
- 修改某次生成的地图不会影响其他地图及再次生成的结果。

读写测试使用临时目录，不覆盖真实保存的地图。

最终运行结果：34 passed in 0.18s。

0.18秒是本次整套测试的运行时间，不是单个寻路算法的耗时。界面按钮、暂停调速和表格刷新仍采用人工验证。

## 六、最终状态与剩余局限

第一轮记录中的17项测试属于早期阶段结果；当前最终结果为34项自动化测试通过。

系统现已具备互动迷宫、三种寻路算法、搜索记录回放、暂停调速、地图保存加载、预设地图和窗口内性能对比。

第一轮中“关闭后地图无法保留”的局限已由保存加载功能解决，但需要用户主动保存，且目前只使用一个固定地图文件。

当前仍存在以下局限：

- 主要面向Windows，中文字体依赖本机字体路径。
- 窗口与网格尺寸固定。
- 动画属于搜索记录回放。
- 性能测量用于教学比较，不是全面的算法性能评估。
- 自动化测试未覆盖所有地图和界面交互。
